# fix_notes — R6-fix-analyze-4: вернуть nullable MessageCost (откат heal2 к main)

## Что было не так

heal2 в R6-3 «восстанавливал» `message_part.dart` по fetched-версии **main**
(f4db9ed) + логу анализатора. Но main не содержит R4: зелёный контракт R4 —
это коммит 20340ea ветки agent, где `MessageCost.cost` — `double?`. В
результате heal2 молча откатил nullable-контракт к non-nullable (cost:
`final double cost;`, валюта по умолчанию 'USD', formatted =
`toStringAsFixed(2)`, fromJson `?? 0` / `?? 'USD'`). Тесты R4 упали:
`expect(cost.cost, isNull)` и `expect(cost.formatted, '1,875 ₽')` —
неизвестная сумма подменялась нулём, а валюта без данных — долларом.
Откат также «затер» адаптации потребителей (_addKnownRub/_sumRoundCosts,
_costWidgets), которые при non-nullable вынужденно трактовали «нет суммы»
как `cost: 0` — прямое нарушение принципа R4 «неизвестное не ноль».

## Что сделано (мердж, не восстановление из 20340ea целиком)

1. **message_part.dart** — мердж: nullable MessageCost из 20340ea
   (`double? cost`, валюта по умолчанию `''`, formatted сохраняет точность
   — '1,875 ₽' — и возвращает 'Стоимость неизвестна' при null, fromJson
   без дефолтов 0/'USD', fromUsage: cost_rub → 'RUB', unscoped 'cost' →
   валюта пустая, не USD) + СОХРАНЕНО из heal1: `PendingPart.indeterminate`
   и `UnknownPart`.
2. **UnknownPart** — теперь ОТДЕЛЬНЫЙ лист sealed-иерархии (не подтип
   TextPart): честная типизация, `is TextPart` больше не ловит UnknownPart.
   В `MessageView._partsWidgets` добавлена явная ветка `case UnknownPart():
   break;` (часть по-прежнему не рендерится, данные сохраняются при
   round-trip — регрессии к «пустому тексту» нет). Других исчерпывающих
   switch по MessagePart в присланном коде нет; если CI найдёт ещё где-то
   — туда нужна такая же явная ветка.
3. **chat_screen.dart** — отменены non-nullable адаптации heal2:
   `_addKnownRub` снова проверяет `cost == null`; `_sumRoundCosts` суммирует
   только известные суммы (null cost / пустая валюта раунда пропускается);
   при конфликте валют или отсутствии сумм итог — cost null + пустая
   валюта, только токены. Никаких `cost: 0` и 'USD' по умолчанию.
4. **message_view.dart** — `_costWidgets`: сумма показывается только при
   `cost != null` И непустой валюте; иначе — только счётчики токенов.
   `_PartPending`: при `PendingPart.indeterminate == true` показывает
   неопределённую индикацию (null value + подпись «в процессе…») вместо
   выдуманного процента.
5. **chat_message.dart** — добавлена ветка `case 'text'` в `_decodePart`:
   TextPart после перезапуска восстанавливается с cost (MessageCost.fromJson)
   и sources, стоимость/источники больше не теряются (раньше часть
   декодировалась как UnknownPart('text')).
6. **Кейс JobStatusUnknown в GenErrorMapper.detailsOf** — сохранён, не тронут.
   TEMP-DIAG-UNMODIFIABLE не тронут. Существующие импорты (включая
   `ignore: unused_import`) не удалялись.
7. **ToolMedia — решение**: оставлен ЕДИСТВЕННЫЙ объявленный класс в
   `tool_media.dart` (heal2 восстановил его корректно); message_part.dart
   класс НЕ содержит, shim-экспорта нет, потребители (chat_service,
   chat_screen, generation_event, model_tool_stream) импортируют
   tool_media.dart напрямую. Перенос в message_part.dart потребовал бы
   одновременной правки всех show-импортов — риск без пользы; переносить
   стоит только если появится второй потребитель, которому неудобен
   отдельный файл. Замечание TEMP-SHIM в tool_media.dart устарело
   (не критично).
8. **Потребители MessageCost проверены**: cost_estimate.dart и
   active_model_controller.dart MessageCost не используют; chat_service.dart
   только импортирует message_part.dart (неиспользуемый импорт сохранён по
   правилам проекта). Подмен «неизвестно → 0/USD» в присланном коде больше нет.
9. **Незакрытый блок @@@FILE из R6-3**: по присланному состоянию (261d63b)
   все вещи из области R6 на месте (indeterminate, UnknownPart, JobStatusUnknown,
   диагностика PendingPart) — файл, который не применился в R6-3, видимо,
   был именно message_part.dart, и его «применение» heal2/heal1 как раз и
   создало дефект. Отдельный неприменённый файл по присланному коду
   не identified — если что-то ещё должно было примениться, пришлите список.

## Что стоит улучшить рядом (сейчас НЕ чиню)

- Прогресс видео-задачи, когда провайдер не сообщает процент, всё же
  генерируется эвристикой (_defaultPercent) и пишется в ActiveJobsStore;
  UI теперь показывает indeterminate, но сохранённый «плавный» процент
  в снимке остаётся выдуманным числом — можно хранить явный флаг.
- MessageCost.symbol/formatted для известных не-USD/RUB валют показывает
  код валюты как есть — можно завести таблицу символов, если понадобятся.
- partSchemaVersion не поднимался: decode 'text' обратно совместим,
  но при следующих изменениях формата частей поднять до 3.
- Тест на decode/encode round-trip TextPart с cost/sources отсутствует
  в присланном наборе — стоит добавить (шаг 7 покрыт только кодом).

## Как проверить живым тестом (пользователь)

1. **Честная стоимость**: отправить запрос текстовой модели с включённым
   «показывать стоимость». Если провайдер вернул usage с cost_rub — под
   ответом строка `≈ <сумма> ₽ · N ток.`, точность не обрезана
   (например, 1,875 ₽ не превращается в 1,88 ₽).
2. **Нет суммы ≠ ноль**: модель/провайдер без стоимости в usage — строка
   стоимости показывает только `N ток.` (без `≈ 0,00 ₽`, без '$0,00').
3. **Источники**: режим поиска с источниками — блок «Источники» появляется
   под ответом и сохраняется после перезапуска приложения (ветка decode
   'text').
4. **Видео**: запустить видео-модель, у которой провайдер не отдаёт
   процент, — в карточке ожидания вращающаяся неопределённая индикация
   и «в процессе…» (не прыгающий выдуманный процент); отмена по крестику
   работает; после перезапуска приложения незавершённая задача
   возобновляется без новой оплаты.
5. **Регрессия R1–R5**: повтор изображения/видео из снимка, диалог с
   инструментами, полная стоимость чата (суммируются только рублёвые
   суммы) — всё как до фикса.
