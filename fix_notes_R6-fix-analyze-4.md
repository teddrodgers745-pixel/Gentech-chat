# R6-fix-analyze-4-heal1 — что было не так и что сделано

## Причина (не симптом)
Сборка упала не из-за логики кода, а из-за того, что в коммит R6-fix-analyze-4 (e61bb38, ветка agent) четыре файла записались ВМЕСТЕ с markdown-ограждением из ответа предыдущего исправления:
- первая строка каждого файла — ` ```dart `;
- последняя строка каждого файла — ` ``` `.

Подтверждено по фактическому содержимому упавшего коммита (raw-файл chat_screen.dart на SHA e61bb38 начинается с ` ```dart `).

Это объясняет ВСЕ 136 сообщений анализатора:
- `expected_executable` x3 в строке 1 (столбцы 1–3 — три бэктика) + `Undefined class 'dart'` + `Expected ';'` (слово `dart` после бэктиков) — строка 1 всех четырёх файлов;
- поток `directive_after_declaration` по импортам (строки 4–58 в chat_screen.dart, ровно с пропуском на пустой строке 6; 4–6 в chat_message.dart; 4–35 в message_view.dart) — импорты «после объявления» из фейковой декларации `dart`;
- `expected_executable` x3 в последней строке (342 / 350 / 1365 / 2244) — закрывающее ограждение из трёх бэктиков;
- внутренние ошибки chat_screen.dart 2191–2232 (`Expected ')'`, `Expected ']'`, dead_code и т.д.) — каскад от сбитого состояния парсера, а не дефекты кода: соответствующие участки чистого кода (хвост `_empty`/`_attachmentActions`) синтаксически корректны, а остальные три файла при том же дефекте начала/конца других ошибок не дают.

## Что поправил
Точечно: убрал строку ` ```dart ` в начале и строку ` ``` ` в конце четырёх файлов:
- lib/core/models/message_part.dart
- lib/models/chat_message.dart
- lib/screens/chat_screen.dart
- lib/widgets/message_view.dart

Содержимое файлов (логика, импорты, комментарии) не менялось — восстановлен ровно тот код, который был в предыдущей зелёной/работающей версии исправления nullable MessageCost. TEMP-DIAG-UNMODIFIABLE не затрагивался.

## Что стоит улучшить рядом (инфраструктура, не код)
- В конвейере «ответ ассистента → файлы репозитория» добавить зачистку markdown-ограждений: если файл начинается с ` ```lang ` и/или заканчивается ` ``` `, срезать эти строки перед записью (или валидировать: `.dart`-файл не может начинаться с бэктика).
- В CI до `flutter analyze` добавить дешёвую проверку-предохранитель (например, grep на `^``` ` в lib/**.dart), чтобы дефект этой категории падал с понятным сообщением, а не со 136 ошибками анализатора.
