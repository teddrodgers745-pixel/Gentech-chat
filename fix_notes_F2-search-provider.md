# F2-search-provider — отчёт

## Что было не так

1. **Режим «провайдер» блокировался не тем условием.** Живой тест 2026-11-27:
   nemotron nano 30b + режим «провайдер» → «модель не поддерживает поиск».
   Режим «провайдер» — это `polza:web_search`, СЕРВЕРНЫЙ инструмент Polza
   (0,50 ₽/вызов): он не зависит от нативного поиска модели и не должен
   проверяться флагом нативного поиска / `webSearchSupported`-probe'ом.
2. **Режим «нативный» включался у модели без нативного поиска.**
   `web_search_options` отправлялся любой Polza-модели, если выбран режим
   «нативный»; у nemotron nano 30b нативного поиска нет → модель имитировала
   поиск выдуманными ссылками. Дополнительно `_onConfigChanged` (chat_screen)
   авто-выставляет `searchMode = 'native'` эвристикой `isHeuristicSearch`,
   что могло маскировать проблему.
3. **Не было запасного пути для моделей без вызова инструментов.**
   Серверный инструмент (`tools`) можно прикрепить только к модели,
   принимающей tool calls; для остальных поиск молча не происходил бы
   (или API вернул бы 400).

## Чего не хватило (файлы не были присланы)

- Строка «модель не поддерживает поиск» **не найдена в присланных файлах** —
  она живёт в UI выбора режима поиска (вероятно `settings_screen.dart`,
  который проверяет probe-флаг `providerSearchSupported`/`webSearchSupported`
  из `AppSettings` и блокирует выбор режима «Провайдер»). Этот файл
  в присланном коде отсутствовал. Сервисный уровень теперь работает
  независимо от того UI-блока, но **рекомендую отдельно убрать/расслабить
  блокировку в settings_screen**: режим «Провайдер» не должен зависеть
  от нативного поиска модели и от probe-флага «web_search tool у провайдера».
- Не присланы `search_capability_resolver.dart`, `active_model_controller.dart`,
  `search_enhancer.dart`, `search_controller.dart` (`chatSearch.enabled`) —
  их контракт сохранён, использованы как есть.

## Что поправил

- `lib/services/chat_service.dart`:
  - `builtinSearchTools`: для Polza — `polza:web_search` в режиме «провайдер»
    безусловно; «нативный» без нативного поиска модели автоматически
    переводится в «провайдер» (реальный поиск вместо выдуманных ссылок).
  - Новый `effectiveSearchMode`: приведение режима к возможностям модели
    (Polza: native без нативного поиска → provider). Используется
    в `_roundOnce`, поэтому `web_search_options` больше не отправляется
    моделям без нативного поиска.
  - Новый хук `toolSupportProbe`: чат-экран подключает `supportsTools`
    каталога активной модели (`null`/ошибка каталога = не блокируем;
    блокируем только явное `false`). Если модель не принимает инструменты —
    поиск уходит в предзапрос «модель-инструмент» (плагин `web` Polza,
    работает с любой моделью), а предзапрос без выбранной поисковой модели
    использует текущую модель с этим плагином.
  - Хук `nativeSearchProbe` — источник «есть ли нативный поиск»:
    по умолчанию `SearchCapabilityResolver`, подменяется тестами.
- `lib/screens/chat_screen.dart`: перед отправкой резолвится
  `supportsTools` активной модели из каталога и подключается в
  `ChatService.toolSupportProbe`.
- `test/f2_search_provider_test.dart`: именованные тесты
  F2-T-PROVIDER-TOOL, F2-T-NATIVE-GATE, F2-T-NATIVE-OK,
  F2-T-PROVIDER-NO-TOOLS, F2-T-SEARCH-OFF, F2-T-NATIVE-POLZA-ONLY.
- TEMP-DIAG-UNMODIFIABLE не тронут (не встречается в присланных файлах);
  фикс F1 и R1–R6 не переписаны.

## Что стоит улучшить рядом (не чинил)

1. settings_screen: убирать блокировку режима «Провайдер» по probe-флагу
   и показывать предупреждение «у модели нет нативного поиска, используется
   провайдерский поиск» при выборе «Нативный».
2. `webSearchSupported`/`providerSearchSupported` — устаревшие probe-флаги:
   после F2 они не должны влиять на Polza-путь; стоит удалить или
   переразметить.
3. Авто-выбор `native` в `_onConfigChanged` стоит гейтить поддержкой
   нативного поиска (или сразу ставить `provider`).
4. Предзапрос «модель-инструмент» с текущей моделью и плагином `web` —
   проверить у Polza фактический формат ответа плагина (citations)
   живым тестом.

## Как проверить живым тестом

1. **F2-LIVE-SEARCH-PROVIDER**: nemotron nano 30b (Polza), настройки →
   поиск → режим «Провайдер». Отправить «найди свежие новости о Flutter».
   Ожидание: реальный поиск (источники под ответом), в body запроса —
   `tools: [{'type': 'polza:web_search'}]`, списание 0,50 ₽ за вызов.
2. **F2-LIVE-SEARCH-NATIVE-GATE**: та же модель, режим «Нативный».
   Ожидание: `web_search_options` в запросе НЕТ; поиск выполняется
   серверным инструментом (фоллбэк), выдуманных ссылок нет.
3. Модель с нативным поиском (по каталогу/эвристике) + режим «Нативный»:
   в body есть `web_search_options`, серверного инструмента нет.
4. Регресс: модель без tools-поддержки + «Провайдер» → в чате карточка
   «Поиск (модель-инструмент)»/источники под ответом, а не 400 от API.
