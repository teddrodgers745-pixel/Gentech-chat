# fix_notes_R4-fix-tests-green-4 — честная стоимость + reasoning-капсула

## Что было не так
1. Переход heal2 на nullable `MessageCost.cost` (double?, валюта '' — неизвестна)
   был сделан только в message_part.dart: оба потребителя в chat_screen.dart
   (`chat.totalCost += imgCost.cost`, `chat.totalCost += usageCost.cost`) и
   `MessageView._costWidgets` (`CurrencyFormat.format(c.cost, ...)`) остались
   под старым контрактом — сборка 6c67721 красная на Analyze Code, а при
   неудачной компиляции падал бы и Run tests.
2. `_generateImage` выдумывал стоимость: неизвестная оценка превращалась
   в 1,5 ₽, USD переводился фиксированным курсом ×95, токены считались из
   длины промпта, и всё это безусловно прибавлялось в totalCost.
3. `_runCompletion` сохранял только последний usage: usage промежуточных
   раундов (вызовы инструментов) терялся, а прибавление в totalCost шло
   без проверки валюты.
4. Reasoning-уровни подставывались дефолтными списками: `reasoning: true`
   без списка и «reasoning» в supported_parameters создавали
   ['off','low','medium','high'] / ['off','high'] — «выдуманные пресеты»,
   запрещённые правилами. В UI капсула при пустом списке просто
   скрывалась, хотя решение пользователя — показывать её неактивной
   с уведомлением.

## Что поправил
- **chat_screen.dart**: `_generateImage` — оценка (CostEstimate) и стоимость
  сообщения разделены: TextPart с MessageCost создаётся ТОЛЬКО при
  `estimate.isKnown` и цене каталога в RUB, с явной `currency: 'RUB'`;
  никакой 1,5 ₽, никакого курса ×95, никаких выдуманных токенов.
  `_runCompletion` — собирает MessageCost КАЖДОГО раунда (usage каждого
  chunk), итог через `_sumRoundCosts`: токены суммируются всегда, суммы —
  только если все раунды с суммой сообщили одну и ту же известную валюту
  (разные валюты → сумма null, токены остаются). В `chat.totalCost`
  попадает только известная рублёвая сумма (`_addKnownRub`). Reasoning:
  если каталог не перечисляет уровни — effort не отправляется вовсе,
  `_cycleReasoning` показывает уведомление вместо смены уровня.
- **message_view.dart**: `_costWidgets` — известная сумма показывается
  через `MessageCost.formatted` (фактическая валюта, точность 1,875 ₽
  сохраняется); сумма без валюты/валюта без суммы — только счётчики
  токенов, без подмены. Импорт currency_format оставлен с
  `// ignore: unused_import` (правило: импорты не удаляются).
- **text_chat_input.dart**: капсула «Мышление» при заявленных размышлениях
  без перечисленных уровней — видима, но НЕАКТИВНАЯ: серый стиль, тап —
  SnackBar «У этой модели нет размышлений»; шторка уровней в этом случае
  не открывается (фолбэк на 6 выдуманных уровней убран). Модель вовсе без
  размышлений капсулу скрывает, как раньше.
- **provider_catalog_service.dart**: `_parseReasoning` больше не
  подставляет дефолтные списки — уровни ТОЛЬКО из `supported_efforts`
  каталога, в исходном порядке (`reasoning: true` и supported_parameters
  → levels=[], reasoning≠null, reasoningUnknown=false). Удалены
  неиспользуемые приватные константы `_defaultReasoningLevels` и
  `_supportedParamsReasoningLevels`.
- **test/provider_catalog_parser_test.dart**: ожидание «reasoning: true →
  4 уровня» заменено на «уровней нет» (новый контракт по решению
  пользователя) + добавлен именованный тест
  T-R4-REASONING-CATALOG-NO-LEVELS (marker / пустая карта / только
  supported_parameters).
- **chat.dart**: только документация totalCost — теперь это рубли.

## Чего не хватило в присланном коде (проверить рядом)
- **active_model_controller.dart НЕ прислан**: работаю в предположении, что
  контроллер переносит `entry.reasoning != null` → `caps.reasoning` (true)
  и `entry.reasoning?.levels ?? []` → `caps.reasoningLevels` как есть. Если
  там `reasoning: levels.isNotEmpty`, неактивная капсула не появится —
  нужно точечно поправить маппинг (не трогая остальное).
- `main.dart`, `settings_screen.dart`, `catalog_entry.dart`,
  `generation_request.dart` не присылались — проверено только по
  использующим их местам из присланного кода.
- Рядом (не чиню сейчас): плашка «Думает…» в MessageView реагирует на
  сохранённый settings.reasoningLevel и не знает про пустые уровни каталога;
  `CostEstimate.estimatedUsd` — легаси-имя для суммы в произвольной валюте;
  history_drawer конвертирует totalCost (теперь всегда RUB) в валюту
  настроек через фиксированные курсы — это осознанное поведение для
  ИЗВЕСТНОЙ рублёвой суммы, отличное от запрещённого перевода «неизвестной»
  валюты.

## Как проверить живым тестом (после зелёной сборки)
1. **T2-LIVE-COST-402**: ключ с лимитом → ответ-карточка «Ошибка оплаты или
   лимита: Превышен лимит ключа», НЕ «недостаточно средств».
2. **Flux klein 16:9 2K**: генерация изображения FLUX-2K → под ответом
   «≈ 1,875 ₽» (не 1,88 и не 1,50); в шторке истории сумма чата выросла
   ровно на 1,875 ₽.
3. **T-R4-LIVE-REASONING-CATALOG**: выбрать модель с `reasoning: true`
   без списка уровней → капсула «Мышление» серая и видимая; тап →
   SnackBar «У этой модели нет размышлений»; в исходящем POST нет поля
   reasoning/reasoning_effort. Выбрать модель с перечисленными уровнями
   (например max/high/low/none) → капсула активна, тап циклически
   перебирает уровни в порядке каталога, шторка показывает только их.
