# Fix notes — R5-text-search-tools-2 (повтор после обрезки)

## Что было не так (по замечаниям Терры, приоритет 5)

1. **Reasoning ремап в чат-экране.** Оборванный файл прошлой попытки —
   `lib/screens/chat_screen.dart` (он не был применён): в `_runCompletion`
   уровень `low` превращался в `medium`, `xhigh/max` — в `high`,
   выключенный уровень — в отсутствие блока reasoning. Противоречит
   требованию «передавать выбор как есть»: отсутствие блока — поведение
   модели по умолчанию, не обязательно «выключено».
2. **Native-поиск = polza:web_fetch.** Применённый `chat_service.dart`
   добавлял серверный инструмент `polza:web_fetch` в режиме `native`
   «исходя из предположения, что нативный поиск означает нативный
   фетчинг». Ни один режим поиска фетчинг не подразумевает.
3. **Медиа-инструмент не материализовался.** `ImagesApiExecutor` никогда
   не эмитил `GenCompleted` (только markdown-дельту), поэтому
   `ModelToolRunner._runMedia` для image-модели всегда падал в
   «не вернула результата», а `StreamChunk.toolMedia` в
   `_runCompletion` (чат идёт напрямую через `ChatService`, не через
   `ChatCompletionsExecutor`) отбрасывался: медиа-результат инструмента
   не превращался в ImagePart/VideoPart и не показывался в чате.
   Прогресс видео-задачи инструмента (toolJobId/toolProgress) тоже
   игнорировался — jobId не сохранялся, восстановления после перезапуска
   не было. Заодно каждый прогресс-чанк создавал НОВУЮ карточку
   tool_call (старый код создавал карточку на каждый running-чанк).
4. **Цепочка вызовов не переживает ход.** `_runCompletion` исключал
   tool_call-сообщения из истории (`!m.isToolCall`), поэтому на следующем
   ходу модель не видела, что вызывала инструмент и что он вернул.
5. **Провайдер/цена.** Тела Polza-запросов не несли выбора провайдера —
   автороутинг по умолчанию не гарантирует самого дешёвого провайдера.

## Что поправлено (точечно, без переписывания применённого)

- **chat_screen.dart (доделан оборванный файл):**
  - reasoning: выбранный уровень уходит как есть (без ремапа); модель без
    заявленных каталогом размышлений — блок не отправляется; адаптивный
    `type/effort_level` не выдумываем (каталог признак не выражает).
  - история: `_buildHistoryMessages` восстанавливает полную
    упорядоченную цепочку (assistant + `tool_calls` → tool-ответ с
    `tool_call_id`); карточки предзапроса поиска (только UI) и карточки
    без результата в историю не попадают.
  - медиа-инструмент: прогресс → PendingPart с jobId (виден после
    перезапуска), результат → ImagePart/VideoPart в том же ответе,
    ошибка инструмента → ожидающая часть снимается; ответ с медиа-частями
    не удаляется как «пустой».
- **chat_service.dart (применённый, точечная правка):** в
  `builtinSearchTools` режим `native` для Polza больше не добавляет
  `polza:web_fetch` — нативный поиск это документированный параметр тела
  `web_search_options` (он добавляется в `_roundOnce`), фетчинг
  отдельным режимом не подразумевается. `provider` → `polza:web_search`.
  Проверено по докам: web-search.md (таблица «Как включить») и
  server-tools.md (полный список серверных инструментов). Остальное
  (предзапрос через `plugins: [{id: 'web'}]` — тоже документирован,
  provider `{sort: price}`, 402 с телом, [DONE]/finish_reason,
  отсутствие повторов после 400) уже корректно в применённом файле.
- **images_api_executor.dart (применённый, точечная правка):** в конце
  `run` эмитится `GenCompleted` с локальным путём и/или удалённой
  ссылкой (существующие потребители — `_generateImage` — событие
  игнорируют, контракт только расширяется). Теперь `ModelToolRunner`
  получает типизированный адрес результата для image-модели-инструмента.

## Чего не хватило / что стоит улучшить рядом (не чиню сейчас)

- **Не присланы:** `core/utils/reasoning_mapper.dart` (сверял контракт
  по местам использования: `.id`, `.name`, `fromId`), дока reasoning
  про адаптивный режим — в этой работе содержимое reasoning-tokens.md не
  проверялось (проверен индекс, web-search, provider-selection,
  server-tools).
- **Медиа-fallback'и** (`defaultMediaParams`, `ImageGenMode.aspectRatios`,
  `'1:1'` в `_generateImage`) остались как есть — свести с правилом
  «только значения каталога» отдельной задачей.
- **Восстановление image-задач инструмента** после перезапуска:
  `restorePendingJobs` возобновляет только `AsyncJobExecutor` (видео);
  image-задача в `ActiveJobsStore` остаётся без опроса. Стоит добавить
  image-ветку восстановления.
- **Отмена медиа-задачи инструмента**: `_stop` отменяет `ChatService`/`_genService`,
  но исполнитель, созданный внутри `ModelToolRunner`, не регистрируется
  в `_running` — стоит прокинуть отмену.
- **Проверка поддержки tools** моделью перед отправкой `tools`
  (`supportsTools` из каталога) — Terra упоминала, в задачу R5 не входила.
- **`provider` в теле ответа** (`"provider": "openai-direct"`) —
  можно показывать в карточке ответа, полезно для T2-LIVE-PROVIDER-PRICE.

## Как проверить живыми тестами (T2-LIVE-*)

- **T2-LIVE-TEXT-REASONING:** выбрать модель с перечисленными каталогом
  уровнями (например `max`/`none`); выставить каждый уровень, отправить
  запрос; по логу/прокси убедиться, что в теле `reasoning.effort` уходит
  РОВНО выбранный уровень (low не превращается в medium, max — в high),
  `off` → явный `none`, у модели с `mandatory` — блока нет. Модель без
  размышлений — блока нет вовсе.
- **T2-LIVE-SEARCH-FETCH:** режим «Нативный» на Polza — в теле запроса
  появляется `web_search_options: {}`, `polza:web_fetch` НЕ появляется;
  режим «Провайдер» — `tools: [{"type":"polza:web_search"}]`, источники
  и `usage.cost_rub` с поиском (0,50 ₽/вызов) в карточке; режим
  «Модель-инструмент» — предзапрос с `plugins:[{"id":"web"}]`, источники
  и usage предзапроса в чате, при недоступной поисковой модели — карточка
  ошибки поиска, а не молчание; отдельно открыть публичную текстовую
  страницу через polza:web_fetch (запросить модель прочитать URL).
- **T2-LIVE-MODEL-AS-MEDIA-TOOL:** настроить в пресете инструмент типа
  «модель» на image-модель каталога; попросить текстовую модель
  «нарисуй кота через инструмент»; проверить: карточка вызова с
  аргументами → прогресс (для видео-задачи — проценты) → картинка в том
  же сообщении (ImagePart) → текстовая модель продолжает ответ; проверить
  следующий ход — модель помнит вызов (в теле запроса assistant с
  `tool_calls` и tool-ответ); для видео — перезапустить приложение и
  убедиться, что задача возобновляется по jobId, без новой оплаты.
- **T2-LIVE-PROVIDER-PRICE:** в теле и чата, и медиа-запросов присутствует
  `provider: {sort: "price"}` (настройка `providerSort`, по умолчанию
  price); сравнить цену одинакового запроса с `sort: price` и без
  provider — подтверждение, что автороутинг не всегда самый дешёвый.
