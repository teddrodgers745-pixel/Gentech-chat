# R2-job-lifecycle: замечания

## Статус

Задача **не завершена и не принята**. Внесено только ограничение области
локальной остановки в `GenerationService` и уточнено сообщение при
невозможности восстановить подключение к известной задаче.

Сборка и именованные живые тесты не выполнялись: в присланном материале нет
исполняемого проекта, тестового окружения и доступа к платному аккаунту.
Изменение нельзя считать проверенным исправлением жизненного цикла.

## Что было не так и что изменено

- `GenerationService.cancel()` вызывал глобальный
  `AsyncJobExecutor.cancelAll()` и тем самым мог затронуть задачи других
  сессий. Этот вызов убран. Исполнители фонового восстановления больше не
  добавляются в набор исполнителей текущей сессии.
- При отсутствии адреса или ключа для известного ID `resumeJob` советовал
  отправить запрос заново. Теперь ошибка сохраняет ID и предупреждает о
  возможном повторном списании.

Это **не** исправляет локальную отмену внутри `AsyncJobExecutor`: она
по-прежнему может удалить запись текущей задачи и сообщить об отмене без
подтверждения сервера. Остановка изображения также остаётся локальной.
Другие возможные вызовы `cancelAll()` вне присланного кода не проверены.

## Что остаётся исправить

1. До POST надёжно сохранять намерение создания с привязкой к чату и
   сообщению. При неоднозначном результате POST сохранять состояние
   «создание не подтверждено» и не отправлять POST повторно автоматически.
   Даже при немедленной записи ID остаётся окно между ответом сервера и
   записью на диск; без документированной идемпотентности или поиска задачи
   у провайдера его нельзя гарантированно устранить.
2. После получения ID сохранять его вместе с маршрутом, состоянием и
   устойчивыми идентификаторами чата и сообщения для изображений и видео.
   При восстановлении идемпотентно создавать недостающий `PendingPart` или
   сообщение. Не удалять запись о готовом результате до надёжного сохранения
   результата в чат. Ошибки сохранения показывать пользователю.
3. Проверить по актуальной документации Polza, поддерживается ли серверная
   отмена и как подтверждается её результат. Не выдумывать endpoint. Если
   подтверждения нет, сохранить задачу, предупредить о возможном списании и
   продолжить либо предложить продолжить опрос того же ID.
4. Различать terminal failed и неизвестный статус. Ошибки опроса, авторизации
   и таймаут не доказывают terminal-состояние. При подтверждённом terminal
   failed очищать ID снимка; новая платная генерация требует явного
   подтверждения.
5. Организовать единое наблюдение за каждой задачей с учётом провайдера и
   подключения. Исключить гонку фонового восстановления и ручного повтора,
   параллельно восстанавливать разные задачи и показывать ошибки вместо
   подавления исключений.
6. Сохранять снимок текстового запроса, включая фактическое содержимое
   вложений и настройки. При повторе проверять адрес и идентичность
   исходного подключения, не сохраняя секрет в снимке; если восстановление
   невозможно, явно сообщать об этом.
7. Захватывать `_streaming` до первого `await` и освобождать в `finally`,
   включая ранние выходы и ошибки.
8. Сериализовать изменения хранилища задач: текущие `loadAll` → изменение →
   `_persist` могут терять конкурирующие обновления. Не подавлять ошибки
   записи. Ключ API сейчас хранится в `SharedPreferences` в открытом виде;
   перенос секретов в защищённое хранилище стоит рассмотреть отдельно.

## Чего не хватило

Не присланы `terra_review.md`, `lib/core/storage.dart`, `lib/app_state.dart`,
`lib/models.dart`, `lib/services/chat_service.dart`,
`lib/widgets/message_view.dart`, определения `generation_event.dart`,
`generation_request.dart`, `generation_executor.dart`, остальные потребители
событий и частей сообщения, конфигурация проекта и тесты. Без них нельзя
надёжно проверить атомарность сохранения, все маршруты и всех потребителей
новых состояний. Начальная страница документации Polza не подтверждает
наличие API отмены или идемпотентного создания.

## Живая проверка после полного исправления

Использовать реальные недорогие модели и допустимые параметры из актуального
каталога Polza; заранее установить бюджет. Не включать ключи в логи и отчёт.

- **T2-LIVE-IMAGE-LIFECYCLE:** создать изображение через `/media`,
  зафиксировать ID и факт его сохранения, дождаться результата и локального
  файла, проверить карточку, перезапустить приложение и проверить изображение
  в том же чате.
- **T2-LIVE-VIDEO-RESTORE:** создать видео, зафиксировать ID и число POST,
  перезапустить приложение до завершения. Проверить GET для того же ID,
  отсутствие нового POST и появление результата в исходном чате.
- **T2-LIVE-RETRY-CANCEL:** остановить ожидание после получения ID. Проверить,
  что UI не утверждает неподтверждённую серверную отмену, запись сохранена,
  опрос того же ID продолжается и новый POST возможен только после явного
  подтверждения пользователя.

Дополнительно нужны проверки неоднозначного таймаута POST, terminal failed,
отсутствующего `PendingPart`, конкурентного восстановления и повторного
нажатия отправки. Для каждого теста сохранить обезличенный протокол с ID,
числом запросов и результатом после перезапуска.
