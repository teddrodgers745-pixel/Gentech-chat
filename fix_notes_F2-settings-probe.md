# fix_notes_F2-settings-probe

## Что было не так (разбор дефекта)

Условие показа красного баннера «Текущая модель не поддерживает поиск»
жило ТОЛЬКО в `lib/widgets/search_settings_section.dart` (в
`settings_screen.dart` баннера нет — только `SearchSettingsSection`).
Метод `_providerDetail(p)` переключался по `_probeState` и в ветке
`_ProbeState.unsupported` рендерил красный баннер с кнопкой
«Повторить» через `_banner(border: _red, ...)`.

`_probeState` становился `unsupported`, когда `probeWebSearchSupport`
(из `lib/services/search_probe.dart`) возвращал
`WebSearchProbeResult.unsupported`: проба отправляла
`POST /chat/completions` с `tools: [{'type': 'web_search'}]` — legacy
OpenAI-тип инструмента, — и ответ 400 трактовался как «модель не
поддерживает поиск». То есть баннер гейтил режим «Провайдер»
поддержкой legacy-инструмента, что прямо противоречит контракту F2:
`polza:web_search` — серверный инструмент Polza, независимый от
нативного поиска модели. По документации Polza
(docs/gaidy/server-tools.md) серверные инструменты работают со всеми
моделями с вызовом функций, а `polza:web_search` — даже с моделями БЕЗ
вызова функций (Polza выполняет поиск как плагин `web` до обращения к
модели, 0,50 ₽ за вызов). Проба legacy-типа для Polza в принципе не
отражает поведение чата: `ChatService.builtinSearchTools` в Polza-ветке
`webSearchSupported` вообще не читает. Дополнительно `settings.webSearchSupported`
и `settings.providerSearchSupported` проба выставляла ложно (`false`
для Polza-моделей), что создавало второе, противоречащее чату, правило.

Побочно: `_runProbe` при пустых Base URL/ключе/модели показывал
«Для проверки задайте Base URL…» — тоже ложное требование для режима,
который не требует пробы.

## Что поправил

1. **Режим «Провайдер»** (`_providerDetail`): проба, баннеры и кнопка
   «Повторить» удалены полностью — режим больше не гейтится ничем и
   НИКОГДА не показывает «Текущая модель не поддерживает поиск».
   Вместо них — спокойное пояснение: поиск выполняет сервер Polza
   инструментом `polza:web_search` (для не-Polza — на стороне
   провайдера), плюс строка про фоллбэк: если модель не принимает
   вызовы инструментов, поиск выполняет предзапрос моделью-инструментом
   (это фактическое поведение `ChatService._roundOnce`, включая
   `modelAcceptsTools`/`toolSupportProbe` — описано честно).
   Авто-пинг (`_runProbe` в `initState` и `_onModeChanged`) убран.
2. **Режим «Нативный»** (`_nativeDetail`): ОДНО правило с чатом —
   эффективный режим считает `ChatService.effectiveSearchMode`
   (тот же вызов, что в `_roundOnce`; в проде оба читают
   `SearchCapabilityResolver` через `nativeSearchProbe = null`,
   в тестах — один и тот же probe-хук). Если «нативный» у модели
   без нативного поиска переводится в «провайдер», секция показывает
   спокойную информационную подпись «У модели нет нативного поиска —
   будет использован поиск провайдера Polza.» — не красным цветом,
   без кнопки. У модели с нативным поиском — прежний текст.
3. **«Повторить»**: удалена вместе с пробой там, где проба больше
   не нужна (режим «Провайдер»); мёртвой кнопки не осталось нигде.
4. **Виджет-тесты** (`test/f2_settings_probe_widget_test.dart`):
   - `F2-T-SETTINGS-PROVIDER-NO-BANNER`: провайдер + модель без
     нативного поиска → баннера/кнопки/спиннера нет, спокойное
     пояснение есть;
   - `F2-T-SETTINGS-NATIVE-CALM`: нативный + та же модель →
     информационная подпись, не ошибка;
   - `F2-T-SETTINGS-NATIVE-OK`: нативный + модель с нативным поиском →
     прежнее пояснение.
5. Удалены ставшие мёртвыми: enum `_ProbeState`, поля `_probeState`/
   `_probeError`, метод `_runProbe`, баннерный хелпер `_banner`,
   константы `_green`/`_red`. Импорт `search_probe.dart` сохранён
   (правило проекта — не удалять существующие импорты) с
   `// ignore: unused_import`. Обновлены док-комментарии класса.
6. TEMP-DIAG, R1–R6 и F1–F5 не затронуты. `settings_screen.dart`
   не менялся: баннер там не жил. Чат не менялся: путь
   UI → ChatService → `_roundOnce` → `builtinSearchTools`
   (`polza:web_search` → «Источники:») уже соответствует контракту F2.

## Чего не хватило в присланном коде

- `lib/services/search_probe.dart` не был прислан — я не менял payload
  самой пробы (legacy `{'type': 'web_search'}`), только исключил пробу
  из UI. Если пробу решите вернуть для не-Polza провайдеров — файл
  понадобится.
- `lib/core/generation/search_capability_resolver.dart` не прислан —
  но он и не менялся: правило «одно с чатом» достигнуто вызовом
  `ChatService.effectiveSearchMode`, а не копией эвристики.
- `lib/core/storage.dart` не прислан — `_loadToolModels` оставлен
  как есть.

## Что стоит улучшить рядом (не чинил сейчас)

- Флаги `settings.webSearchSupported` / `settings.providerSearchSupported`
  больше не обновляются пробой: Polza-ветка чата их не читает, но
  не-Polza legacy-путь (`builtinSearchTools` + `web_search`) опирается
  на `webSearchSupported`, который теперь замораживается в последнем
  сохранённом значении. Если legacy-путь жив — стоит либо обновлять
  флаг только для не-Polza подключений, либо выкинуть флаг целиком.
- Авто-пробу можно вернуть как НЕблокирующую телеметрию (зелёная
  метка «сервер подтвердил инструмент») без гейтинга режима.
- Подписи могли бы учитывать `supportsTools` каталога активной модели
  (грузится асинхронно) и писать в секции «Нативный» точный фоллбэк
  (провайдер vs модель-инструмент) вместо обобщённого текста.

## Как проверить живым тестом (F2-LIVE-SETTINGS-PROBE)

1. Настройки → ПОИСК → «Режим поиска» = «Провайдер», модель
   `nvidia/nemotron-3-nano-30b-a3b`: под выпадающим списком —
   спокойный серый текст про `polza:web_search`, НЕТ красного баннера
   и кнопки «Повторить».
2. Там же «Режим поиска» = «Нативный» на той же модели: подпись
   «У модели нет нативного поиска — будет использован поиск
   провайдера Polza.» спокойным цветом (не красным).
3. Вернуться в чат с той же моделью, включить поиск капсулой,
   спросить про свежие новости: поиск выполняется, под ответом блок
   «Источники:» с чипами.
4. Переключить режим на «Нативный» для модели С нативным поиском:
   подпись «Поиск выполняется самой моделью…», предупреждений нет.
