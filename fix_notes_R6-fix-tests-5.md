# fix_notes — R6-fix-tests-5

## Падавшие тесты (Run tests, коммит 4ec55cb, run 45947997017)

1. `test/r4_402_mapper_widget_test.dart` — `T-R4-402-STATUS-MAPPER: HTTP-статус важнее цифр в тексте`
   Ошибка: Expected `RateLimited`, Actual `InsufficientFunds` («Провайдер упомянул 402...», statusCode: 429).
2. `test/r4_402_mapper_widget_test.dart` — `T-R4-402-MAPPER-WIDGET: причина лимита видна без утверждения о балансе`
   Ошибка: Expected `InsufficientFunds`, Actual `UnknownGenError` («Превышен лимит ключа.», statusCode: 402). Падение на expect в строке 33 — до рендера ErrorBubble дело не дошло.

## Виновник: КОД (тесты соответствуют R4-контракту)

- `lib/core/models/gen_error_mapper.dart`: `fromException` для `ChatServiceException` вызывал `_fromText(error.message)`, игнорируя `error.statusCode`. Фикс: при известном statusCode > 0 — `_fromStatusCode(status, error.message)`; текстовый разбор — только когда статус неизвестен. Теперь 429 с «402» в тексте → `RateLimited` (details содержат «402»), 402 без цифр в тексте → `InsufficientFunds`.
- `lib/features/chat/widgets/error_bubble.dart`: заголовок `InsufficientFunds` был «Недостаточно средств» — прямое нарушение R4-контракта «402 ≠ доказанный недостаток баланса» (см. одноимённый зелёный тест `T2-UNIT-COST-402`). Фикс: заголовок «Ошибка оплаты или лимита», детали провайдера показываются как есть, кнопка «Настройки» сохранена. Заодно во все исчерпывающие switch (`_action`, `_title`, `_icon`) добавлена явная ветка `JobStatusUnknown` (retry / «Статус задачи неизвестен»).

## Чего не хватило

- `lib/features/chat/widgets/error_bubble.dart` не был приложен к задаче — проверен по репозиторию. Если в актуальной версии файла есть расхождения с присланной мной копией сверх описанных правок (заголовок 402 + ветки JobStatusUnknown), сведи их вручную — суть фикса только в этих двух точках.

## Что стоит улучшить рядом (сейчас НЕ чинится)

- Дублирование текста: при реальном 402/429 детали после ремаута содержат уже собранное сообщение `_describeError` (например, «Ошибка оплаты или лимита (402): ...») и рядом с заголовком карточки читаются избыточно. Можно передавать в `ChatServiceException` сырой текст провайдера отдельным полем.
- В details `AuthError` при реальном 401 попадает `tokenPrefix` из сообщения ChatService — был и до фикса, стоит вынести префикс токена из отображаемых деталей.
- `_fromText` остаётся фолбэком для исключений без статуса — покрыть его отдельным тестом, чтобы «402 в тексте без статуса» не потерял обработку.

## Как проверить живым тестом на телефоне

1. Запрос с ключом, у которого исчерпан лимит (провайдер вернёт 402 «key limit exceeded»): в чате карточка ошибки с заголовком «Ошибка оплаты или лимита», под ней причина провайдера (например, «Превышен лимит ключа.»), кнопка «Настройки». Текста «Недостаточно средств» быть не должно.
2. Запрос, вызывающий 429 (частые запросы): карточка «Слишком много запросов», а не «Ошибка оплаты», даже если тело ответа провайдера упоминает 402.
3. Повторить обычный текстовый диалог и генерацию видео — регрессия R1–R5: ошибки таймаута/сети/401 отображаются прежними карточками, «Повторить» работает.
