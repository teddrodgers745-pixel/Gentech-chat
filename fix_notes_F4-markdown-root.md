# fix_notes: F4-markdown-root (убрать двойную запись reply.content при стриминге)

## Что было не так (разбор, п.0 задания)

Взаимодействие двух участников в `ChatScreen._runCompletion`:

1. `ChatService._pacedStream` (lib/services/chat_service.dart, метод
   `_pacedStream`) — ЕДИНСТВЕННЫЙ владелец пейсера: каждый
   `chunk.content` проходит через `pacer.add(...)`, наружу выдаются
   только порции `pacer.onTick` (2–3 символа за кадр) и остаток
   `pacer.flush()` в `onDone`.
2. В `_runCompletion` был слушатель `onPaced()` с
   `reply.content = shown` (перезапись из `pacer.displayed`) — и
   ОДНОВРЕМЕННО цикл `await for (...)` делал
   `reply.content += ch.content`.

Гонка: Ticker в `StreamPacer` синхронно обновлял `displayed` и вызывал
`onPaced` → `reply.content = pacer.shown`; чанк-порция, положенная в
`StreamController` в тот же момент, доезжала до `await for` на
следующем микротаске и конкатенировалась поверх — длина становилась
БОЛЬШЕ `pacer.shown`, условие `shown.length > reply.content.length`
переставало срабатывать, и на стыках куски по 2–3 символа (как раз
половинки `**слово**`) дублировались/рассинхронизировались. Отсюда
«рваный» жирный и литеральные `**`.

## Что поправил

- `lib/screens/chat_screen.dart` (`_runCompletion`):
  - удалён блок `StreamPacer? pacer; void onPaced() { ... }`;
  - удалена подписка `pacer?.displayed.addListener(onPaced)` внутри
    цикла `await for`;
  - удалён `pacer?.displayed.removeListener(onPaced)` после try/catch;
  - оставлено штатное `reply.content += ch.content;` — единственный
    источник `reply.content`, строгая последовательность StreamChunk
    без гонки Ticker/StreamController;
  - подробный комментарий на месте удалённого кода (для следующих
    разборов);
  - импорт `stream_pacer.dart` сохранён по правилам проекта (не удалять
    импорты), помечен `// ignore: unused_import`.
- `repairUnpairedEmphasis` в RichMarkdown НЕ тронута — осталась
  страховкой рендера; Copy (`message.content`) и TTS (`toggleSpeak`,
  `speakAuto`) берут сырой `message.content` и после фикса получают
  целые пары `**...**`.
- Новый тест `test/f4_markdown_root_test.dart` (3 теста на живом
  локальном HttpServer):
  - `F4-T-ROOT-STREAM-ASSEMBLY` — конкатенация чанков равна ответу
    провайдера символ в символ (нет ни дублей, ни потерь), маркеров
    `**` чётное число, `service.activePacer` вычищен после стрима;
  - `F4-T-ROOT-STREAM-BACKLOG` — крупный ответ одной delta: `flush()`
    в `onDone` доставляет хвост целиком (инвариант «ровно один раз»);
  - `F4-T-ROOT-NONSTREAM` — нестримовый путь не менялся.
- Существующие `test/f4_markdown_render_test.dart`, TEMP-DIAG, R1–R6,
  F1–F5, F2-settings-probe, F3-cost-toggle, F1-seedance-restore — не
  тронуты.

## Что стоит улучшить рядом (сейчас НЕ чиню)

- `StreamPacer.displayed` (ValueNotifier) после фикса не имеет
  потребителей в UI — можно в отдельной задаче удалить поле и
  синхронную запись `displayed.value` из tick/flush, оставив пейсер
  чистым генератором порций (минус лишняя работа в кадре).
- `_pacedStream` гейтит порции только по `content`: reasoning
  выдаётся отдельными чанками мгновенно (не под пейсер) — визуально
  норм, но при желании можно печатать и размышления плавно.
- ChatScreen._runCompletion сильно разросся (стрим + инструменты +
  стоимость + файлы) — кандидат на декомпозицию в отдельной задаче.

## Как проверить живым тестом

1. F4-LIVE-MARKDOWN-ROOT: у модели с включённым стримом попросить
   длинный ответ с маркированным списком и жирными заголовками
   («Составь план из 8 пунктов с **жирными** заголовками»). Ожидание:
   жирный ровный с первого слова, литеральных `**` на экране нет.
2. Дождаться конца ответа, нажать «Копировать», вставить в заметки:
   в сыром тексте все пары `**...**` целые (число `**` чётное,
   заголовки открываются и закрываются).
3. Нажать «Озвучить» (TTS): озвучка читает текст без «звёзд-звёзд»
   артефактов и без задвоенных слов на стыках.
4. Повторить 2–3 запроса подряд в одном чате (пейсер/тикер переживают
   несколько раундов) и убедиться, что история не бьётся после
   перезапуска приложения.
